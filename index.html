What each shipped file does

These are the runtime files — the ones you link, inline, or self-host. Everything else in this repo is documentation or authoring tooling and never goes to production.

Stylesheets — link in this order

FileWhat it does
colors_and_type.css Link first. Every design token (the one and only :root), base element styles, and the small utility set (.imgph .photo .lift .reveal). Also carries --ds-version, which lets a live page report which build it loaded.
components.css Link second. Every component as a BEM class, built entirely from those tokens — buttons, cards, fields, chips, tabs, grid, dialog, and the .icon--N size ladder.
styles.css One-tag convenience bundle — @imports the two above in the correct order. Link this instead of them if you prefer a single tag.
editorial.css Opt-in third link, only on editorial pages, always after components.css. Adds --ed-* tokens on a .editorial scope, SharePoint host chrome, hero brand-devices, and the editorial blocks. Never redefines :root. Not in the styles.css bundle.

Script

FileWhat it does
fluent-icon.js Optional. Defines the <fluent-icon name="home-24-regular"> element — authoring sugar over the same sprite the no-JS <use> form reads. Renders into itself (light DOM) on purpose, so <use> can reach the document-level sprite. Skip it entirely and nothing breaks.
alpine.min.js Not in this repo — you self-host it. All interactivity is inline Alpine against the documented state contract. Load it defer, after the markup. There is no behavior layer and no Alpine.data() factory here by design.

Icon sprite — inline once per page

FileWhat it does
fluent-basic-icons.svg The functional Fluent sprite — 48 <symbol>s, ids ic-fluent-{name}-24-regular. App UX affordances: buttons, controls, chrome. Tints via currentColor; size with .icon--N.
The sprite must be inlined into the page body — both icon forms emit same-document #id references, so the symbols have to physically live in the document. A name with no matching symbol renders blank and throws no error.

Fluent icon library — the full set (separate repo, sibling live folder)

The curated fluent-basic-icons.svg sprite carries 48 symbols and is deliberately not meant to grow into the whole Fluent set. When you need more, the complete library — every per-icon SVG, the font builds, and the master index — lives in the separate fluentui-system-icons repo. It is not part of this repo and nothing here resolves a path to it: there is no config key and no build step. In production it is deployed as its own top-level folder, a sibling of bsp-design.

SiteAssets/                       ← the live container
├── bsp-design/                   this design system (see Deploy-BspDesign.ps1)
└── fluent-icons/                 the full Fluent library, deployed separately
    ├── svg/ic_fluent_<name>_<size>_<style>.svg
    ├── FluentSystemIcons-Regular.{woff2,css}
    ├── FluentSystemIcons-Filled.{woff2,css}
    └── fluent-font-library.{json,html}   master index of names + codepoints
NeedDo this
A few icons the sprite lacks Copy the matching real SVG out of the library into fluent-basic-icons.svg as a <symbol id="ic-fluent-{name}-24-regular">, normalized to the 24 viewBox with fill:none + currentColor. Stays on the no-JS <use> path and keeps tinting.
Many icons — breadth, least setup Self-host the icon font instead of growing the sprite: link FluentSystemIcons-Regular.css from the live fluent-icons/ folder and render <i class="icon-ic_fluent_home_24_regular" aria-hidden="true">. No sprite, no JS. Size with font-size — .icon--N does not apply to an <i>. Always aria-hidden the <i> and label the interactive parent; PUA glyphs announce as nothing or garbage otherwise.
One-off, no sprite edit Reference the per-icon SVG by URL exactly like an Abacus icon: <img class="icon icon--24" src="/…/fluent-icons/svg/ic_fluent_home_24_regular.svg" alt="">. Simplest path, but an <img> can't inherit currentColor — you get the file's own color.
Name mapping The system's name token home-24-regular maps to SVG filename ic_fluent_home_24_regular.svg and font class icon-ic_fluent_home_24_regular — the same -→_ transform each time. Full names and codepoints: fluent-font-library.json.
Still first-party Fluent, not a third-party icon kit — so it doesn't breach the "no third-party UI/icon libraries" rule. Don't subset the font to shrink it: that needs a build step, which does breach the buildless rule. Ship the full woff2, or stay on the ~17 KB curated sprite. Detail: TECHNICAL-REFERENCE.md §6.

Versioning & deployment

The repo root VERSION file is the source of truth.

TaskHow
Check a live page's version From devtools: getComputedStyle(document.documentElement).getPropertyValue('--ds-version'). Every shipped CSS/JS file also carries a /*! … v1.0.0 … */ banner on line 1.
Bump the version pwsh ./tools/Set-Version.ps1 1.1.0 — stamps the banners and --ds-version. Review the diff, commit, tag.
Deploy pwsh ./tools/Deploy-BspDesign.ps1 — a pure copy of the runtime files into bsp-design/ inside the synced Code-library folder (C:\dev\fcuportal-code). Add -WhatIf to preview; -Destination to target anywhere else. Full detail in README.md.
