BMO SharePoint design system · editorial mode

Editorial component library

Every editorial-layer block as a token-built CSS class — the warm, employee-facing content register. Link colors_and_type.css → components.css → editorial.css, put content under class="editorial", copy the markup, wire behaviour with Alpine.

Layer: editorial.css (link after components.css) Scope: .editorial Icons: bmo-icons.svg + bmo-content-icons.svg
Two registers, one layer. Editorial blocks come in a showcase form (8px radius, subtle elevation — destination pages) and a mesh form (flat, hairline, square — sits flush beside out-of-box SharePoint web parts). Mesh is a modifier away: .card--quiet, .player--flat, .key-messages--quiet (heroes are always flat) — and the mesh-native blocks (.news-list, .quicklink, .related, .webpart) have no elevation at all.

Hero devices

One brand device per hero, never stacked. Full-bleed devices (--band, --scrim, --blue, --bokeh) build on .hero.hero--banner; --arc builds on the two-column base hero. All heroes are flat/flush — square corners, no elevation — like the OOB SharePoint hero web part.

Blue band — the BMO Central home treatment
Translucent BMO-blue panel over a full-colour photo, heaviest behind the text (≤85% blue). The default when blue should clearly carry the frame.

Flat, hairline forms that sit flush beside out-of-box SharePoint web parts — no elevation, square or 4px corners, dividers over boxes. Reach for these when editorial content shares a page with OOB web parts and must not read as a designed island.

Spotlight slider

The .key-messages shell: media left, one message right, dot + arrow nav. Slides can be quotes or any spotlight content (eyebrow + title + text + link). --quiet flattens it for the mesh register.

Quote form — live demo

<div class="key-messages" x-data="deck()">
  <div class="key-messages__media"><img :src="slides[i].img" alt=""></div>
  <div class="key-messages__body">
    <p class="key-messages__quote" x-text="slides[i].quote"></p>
    <p class="key-messages__cite"><strong x-text="slides[i].name"></strong> · <span x-text="slides[i].role"></span></p>
    <div class="key-messages__nav">
      <button class="key-messages__arrow" aria-label="Previous"
              x-on:click="i = (i + slides.length - 1) % slides.length">…chevron-left…</button>
      <div class="key-messages__dots" role="group" aria-label="Choose a message">
        <template x-for="(s, k) in slides">
          <button class="key-messages__dot" :class="{ 'is-active': i===k }"
                  :aria-pressed="i===k" x-on:click="i=k"></button>
        </template>
      </div>
      <button class="key-messages__arrow" aria-label="Next"
              x-on:click="i = (i + 1) % slides.length">…chevron-right…</button>
    </div>
  </div>
